Hub 列出工作区中的每个 [skill](/skills) 和插件。每个项目会显示它的来源、版本，以及来源中是否有更新版本。

## 来源

来源是 Multica 检查更新的位置。工作区的管理员和所有者可以在 Hub 的 **Sources** 标签页添加来源。

| 类型 | 指向的内容 |
|---|---|
| **GitHub** | 一个代码仓库，可选分支或标签，以及子目录 |
| **Zip URL** | 一个 HTTP 或 HTTPS 地址上的 `.zip` 或 `.skill` 压缩包 |
| **Skills.sh** | 发布在 skills.sh 上的 skill |
| **ClawHub** | 发布在 ClawHub 上的 skill |
| **Registry** | 你自己托管的索引文件（JSON），列出项目及其下载地址 |

**Sync now** 会检查来源中的每个项目。编辑来源时，还可以设置自动同步间隔。删除来源时，需要选择如何处理它的项目：保留（项目会留在 Hub 中，但不再关联来源），或一并删除。如果智能体正在使用其中任何项目，删除会被阻止。

## 添加项目

在 Hub 中选择 **Add**。对话框提供四种方式：

- **From URL**：预览 GitHub 仓库、zip、skills.sh 或 ClawHub 来源，然后导入。
- **From registry**：从你已添加为来源的 registry 中选择项目。
- **Upload**：拖入 `.zip`、`.skill` 压缩包或文件夹。
- **Blank**：创建一个空白 skill。

每次导入都会先经过扫描，然后才会安装。扫描结果为 **No issues**、**Warnings** 或 **Blocked**。被阻止的导入无法安装。有警告的导入需要先确认才能提交。如果已存在同名项目，你可以用新名称导入、替换原有项目，或跳过本次导入。

## 项目页面

打开项目即可查看详情。标签页包括：

- **Files**：浏览、预览和编辑项目的文件。Skill 的修改会直接保存。插件已发布的版本不可更改：修改会形成草稿，直到管理员或所有者发布新版本。
- **Overview**：项目的 README 或清单，以及版本列表。
- **Versions**：项目的历史版本。Skill 可以恢复到更早的版本。
- **Usage**：使用某个 skill 的智能体，或插件在工作区中的安装情况。
- **Source**：项目的来源及其跟踪状态。
- **Activity**：这个项目发生过的变更。

成员可以查看 Hub。能够编辑 skill 的人可以编辑其文件。只有管理员和所有者可以管理来源、发布插件版本和导出。

## 更新与分叉

当项目的来源有更新版本时，项目会显示 **Update available**。打开项目，查看变更的文件和差异，然后应用更新。如果你在本地修改过项目，可以选择以下两种方式之一：

- **Overwrite**：用来源的版本替换项目，本地修改会丢失。
- **Fork**：保留你的修改。项目会与来源分离，不再接收更新。

Hub 不会静默覆盖任何项目。项目的跟踪状态为 **Tracking**（跟随来源）、**Forked**（已分离）或 **Manual**（没有来源）之一。

## 活动

每个项目以及整个工作区都有活动记录。它会记录来源的添加、修改和同步，导入，已应用的更新，分叉，文件保存，插件版本发布，以及导出。每条记录会显示执行人和时间。使用 **Load more** 查看更早的记录。

## 配额

Hub 的用量仪表显示工作区使用了多少项目，以及多少字节的压缩包。默认值为 500 个项目和 1 GiB。自托管用户可以通过 `HUB_MAX_ITEMS_PER_WORKSPACE` 和 `HUB_MAX_STORAGE_BYTES_PER_WORKSPACE` 修改这些值。设为 `0` 表示不限制。

用量达到上限的 80% 时，仪表会显示警告。达到上限后，添加或同步项目会失败并返回配额错误，直到删除一些内容。

## 导出

- 在项目页面选择 **Download bundle**，可下载该项目文件的 zip。每次下载都会生成新的链接，链接在短时间后过期。
- **Export all**（管理员和所有者可用）会在 Hub 中下载一个 zip，其中每个项目一个文件夹（`{kind}/{name}.zip`），并附带一个列出这些项目的 `manifest.json`。

## 文件存放位置

每个项目版本都以不可变压缩包的形式存放在对象存储中。下载、备份和同步都从这里读取。插件的运行时文件保存在数据库中，因此对象存储不可用时，已安装的插件仍能继续运行。关于选择或更换对象存储，请参阅 [Hub 对象存储](/hub-object-storage)。

<Callout type="info">
  Hub 的存储与附件存储相互独立。配置 Hub 存储不会改变现有附件的读取位置。
</Callout>
