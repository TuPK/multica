工作流规定任务经过哪些步骤、每一步由谁处理、要做什么。每个小队处理的任务使用一套工作流。

例如，一套研发交付流程可以这样安排：

| 步骤 | 谁来处理 | 做什么 |
|---|---|---|
| 开发 | 开发智能体 | 完成修改，准备好交给审查。 |
| 审查 | 审查智能体 | 检查结果，通过后交给 QA，需要修改时退回开发。 |
| QA | 团队成员 | 试用结果，确认是否可以完成。 |

把任务移到审查这一步，就会交给审查智能体。任务的描述、讨论和之前的结果都留在原处，下一位处理人可以接着做。

**研发交付**模板就是这个结构。没有分配给任何小队的任务使用 **Default**：所有状态都可用，也不会自动交接，和以前的用法一样。

## 创建工作流

工作区的 `owner` 或 `admin` 可以在网页端或桌面端创建工作流：

<Steps>
<Step>

打开**设置 → 工作流**，选择**新建工作流**。可以从空白开始，也可以使用**研发交付**、**内容生产**或**社区维护**模板。

</Step>
<Step>

填写名称，选择需要的状态列，拖动中间的列调整顺序。

</Step>
<Step>

选择一列，设置任务进入时**不交接**、**交给智能体**或**交给成员**。成员列表里也可以选择**项目负责人**。

</Step>
<Step>

如果交给智能体，写清这一步要做什么，再选择**完成后进入**哪一步（不选时默认进入下一列，但会跳过 Won't Fix 这类已关闭的列；已完成、已关闭类的列默认不往下走）、**打回时退回到**哪一步（这一步认为收到的工作不合格、需要返工时使用）。因外部原因无法继续时用 **Blocked**，不要用退回；只有工作流没有 Blocked 列，或这一步本身是已完成、已关闭类的列时，才改为退回。

</Step>
<Step>

预览智能体会收到的说明，然后保存。

</Step>
</Steps>

如果添加了新状态，先保存工作流，再为这个状态设置交接。

**不交接**会保留原来的负责人。**交给成员**只改变负责人，不启动智能体。**交给智能体**会请它开始处理这一步；你仍需有权限调用它，它所在的电脑也需要在线才能执行。

## 在小队中使用

打开小队，选择它的**工作流**。小队管理者和工作区管理员可以切换。确认窗口会列出小队中哪些任务保留当前状态。如果新工作流没有某些任务正在使用的状态，需要为这些任务选择去处。切换工作流本身不会交接任务，也不会启动智能体。

任务跟随其所在小队的工作流：小队就是任务被分配到的小队，或者被分配的智能体所属的小队。没有工作流的小队不能接收新任务：把任务分配给它时，表单会先要求为该小队选择一套工作流。

项目本身没有工作流。项目看板会按负责其任务的各个小队的工作流显示列，列按这些状态首次出现在任务中的顺序排列。每个任务的状态列表只提供它所在小队工作流中的步骤，并标出进入后交给谁。

### 非流程型小队请求的任务

使用流程的小队会在该流程上运行自己的请求。这类小队的其他任务（例如子任务）则遵循**设置 → 工作流**中的工作区选择：**无操作**（默认，首次会询问你）、**Default**，或你指定的一套工作流。只有工作区管理员可以修改这一选择。

## 把任务交给下一步

修改任务状态，或把卡片拖到另一列。如果这一步设有交接，先确认接收人；交给智能体时，还可以查看它会收到的说明。

<WorkflowDemo />

在小队中新建任务时，如果为任务分配了小队，且任务所在的状态在该小队的工作流中设有交接，任务会直接交给这一步的处理人；处理人是智能体时会立即开始。新建窗口会提示"创建后交给"谁。想先建好再说，可以把任务放在 Backlog。

上一位负责人是智能体、而且它仍在运行或等待开始时，确认窗口会多出停止或取消它的选项，默认勾选。除非想让两位智能体同时处理，保留勾选就行；它已发表的评论和已保存的工作不会丢。

"完成后进入"和"打回时退回到"告诉智能体接下来该把任务移到哪里。一次运行结束不会自行推进任务，状态由负责这一步的成员或智能体更新；智能体把任务移进下一步时，同样会触发那一步的交接。

交接记录和说明会留在任务动态中。在项目看板的工作流菜单中，可以查看完整流程。

## 调整已有工作流

多个小队可以共用一个工作流。在**设置 → 工作流**中保存的修改会对这些小队一起生效。如果只想给一个小队换一套流程，可以复制工作流，再让这个小队使用副本。

管理员也可以直接在项目看板上设置交接：把鼠标移到列头，点击**交给…**，或点击已有的处理人。修改会应用到使用该工作流的小队中的所有任务。

移除一列时，如果还有任务停在那里，需要为它们选择新状态。其他任务保持不变，这次移动也不会启动智能体。工作流列表下方的状态库可以修改状态名称和颜色，使用同一个状态的地方都会同步变化。

删除工作流前，需要先把使用它的小队切换到其他工作流。任务会保留当前状态。

如果**设置**中没有**工作流**，说明当前工作区还不能使用这个功能，状态仍在**设置 → 任务状态**中管理。
