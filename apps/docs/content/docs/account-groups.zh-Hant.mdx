帳號組為組內成員在其角色之上授予額外權限。比如讓財務人員檢視帳單、讓營運人員邀請成員，而不必把他們設為 `admin`。

owner 和 admin 在 **設定 → 帳號組** 中管理帳號組。其他角色看不到這個分頁，也沒有任何權限鍵能開啟帳號組管理，所以沒有人能借助帳號組提升自己的權限。

<Callout type="info">
只有套餐的 `member_groups` 限額大於零時，才包含帳號組。限額為零表示套餐不含該功能，建立帳號組會被拒絕。在預設目錄中，Free 和 Pro 不含帳號組，Business 每個工作區最多 50 個，不限量套餐和 Enterprise 沒有上限。
</Callout>

## 建立帳號組

點選 **建立帳號組**，然後設定：

- **名稱。** 1 到 64 個字元，在工作區內唯一。`Finance` 和 `finance` 視為同一個名稱。
- **描述。** 選填，最多 280 個字元。
- **權限。** 下面六個權限鍵的任意組合。
- **成員。** 搜尋工作區成員並新增。一次請求最多新增 100 人，一個帳號組最多容納 1,000 人。一個人可以屬於多個帳號組，且只能新增目前的工作區成員。

修改在對方的下一次請求時生效，無需重新登入。刪除帳號組或把某人移出帳號組，會立即收回該組授予的權限。

## 六個權限鍵

| 權限鍵 | 開放的內容 |
|---|---|
| `members.invite` | 邀請成員、管理待接受的邀請、建立分享連結。不能邀請 `admin`。 |
| `audit.read` | 查看工作區稽核記錄 |
| `billing.view` | 列出並開啟工作區的訂單及其用量明細，並看到 **帳單與套餐** 分頁 |
| `billing.manage` | 編輯訂單上的買方資訊。包含 `billing.view`。 |
| `integrations.manage` | 連接和中斷 GitHub、版本控制和 Qoder 等整合 |
| `runtime_profiles.manage` | 建立、編輯和刪除自訂執行環境設定 |

owner 和 admin 始終擁有全部六個權限鍵。帳號組為 `member` 角色增加權限鍵，從不移除，多個帳號組的權限鍵會疊加。

<Callout type="warning">
`billing.manage` 目前還不能讓一般成員變更訂閱。購買套餐、變更套餐、新增席位、取消、恢復、帳單資料，以及 **帳單與套餐** 分頁上的用量資料，仍然需要 `owner` 或 `admin` 角色。參見[訂閱](/subscriptions)。
</Callout>

## viewer

帳號組不會讓 `viewer` 獲得寫入權限。屬於帶有 `audit.read` 或 `billing.view` 的帳號組的 viewer，可以讀取該權限鍵開放的內容。即使 viewer 持有對應的權限鍵，每一次寫入仍會被 viewer 角色拒絕。參見[成員與權限](/members-roles)。

## 錯誤

| 提示 | 原因 |
|---|---|
| 已有同名帳號組。 | 名稱與現有帳號組相同，忽略大小寫。 |
| 每個帳號組最多包含 1,000 位成員。 | 帳號組已滿。 |
| 每次最多新增 100 位成員。 | 一次請求中的人數超過 100。 |
| 目前套餐不支援帳號組。 | 套餐的 `member_groups` 限額為零。 |
| 此工作區已達到帳號組數量上限。 | 工作區的帳號組數量已達套餐允許的上限。 |
