platform 服务将货币与支付渠道的选择作为配置数据管理。当前版本仅启用 `vnd`，未内置第二个真实支付渠道。

## 货币（`PLATFORM_CURRENCIES`）

`PLATFORM_CURRENCIES` 指定平台支持的销售货币，以逗号分隔的小写 ISO 货币代码表示，默认值为 `vnd`。

- 当前版本仅启用 `vnd`。配置未启用的货币会导致 platform 启动失败。
- 每个套餐与每笔订单只使用一种货币，金额以该货币最小单位的整数存储（`vnd` 的小数位数为 `0`）。
- 保存套餐时若使用 `PLATFORM_CURRENCIES` 之外的货币，请求会被拒绝并返回 HTTP `400` `price_invalid`（`field: currency`）。
- 系统不进行汇率换算。

## VAT 税率（`BILLING_VAT_RATE`）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BILLING_VAT_RATE` | `10%`（`0.10`） | 适用于 `vnd` 订单的 VAT 税率 |
| `BILLING_VAT_RATE_<CURRENCY>` | `0%` | 适用于其他货币的 VAT 税率；未设置时为 `0%` |

<Callout type="info">
非 `vnd` 货币的 `0%` 默认值仅为技术默认值，不构成税务意见。启用其他货币前，必须由运营方的会计师确认税务处理方式。
</Callout>

## 支付渠道（`PAYMENT_PROVIDERS`）

`PAYMENT_PROVIDERS` 通过逗号分隔的 `currency=provider` 映射为每种货币指定支付渠道。未设置时默认为 `vnd=manual`。

- 启动时必须为 `vnd` 配置一个支付渠道。
- 当订单使用的货币未配置支付渠道或对应渠道已停用时，API 会拒绝创建订单并返回 HTTP `503` `payment_provider_unavailable` 及 `Retry-After` 响应头，且不会写入订单记录。

## 跨币种变更套餐

已有付费订阅的工作区不能变更为其他货币的套餐。此类请求会被拒绝并返回 HTTP `409` `plan_change_unavailable`，原因为 `currency_mismatch`。增购席位与用量账单使用当前订阅的货币。

## 自动银行转账对账（SePay）

默认情况下，`vnd` 使用 `manual` 渠道，由员工在控制台逐笔确认转账。如需自动匹配转账，请启用 SePay webhook 监听端口。员工手动确认仍然可用。

1. 设置支付渠道与监听端口，然后重启 platform：

   ```bash
   PAYMENT_PROVIDERS=vnd=sepay
   PLATFORM_WEBHOOK_PORT=<port>
   PAYMENT_WEBHOOK_SECRET_SEPAY=<SePay 控制台中的 Secret Key>
   ```

   该端口不能与 `PLATFORM_API_PORT`、`PLATFORM_CONSOLE_PORT` 相同。缺少密钥时 platform 拒绝启动。请把密钥放在密钥管理中，不要写入仓库。
2. 在 webhook 端口前部署带 TLS 的反向代理。除控制台外，它是 platform 唯一对外开放的端口。
3. 在 SePay 控制台创建 webhook：方法 `POST`，JSON 请求体，地址 `https://<your-host>/api/payments/webhook/sepay`。把它的 Secret Key 填入 `PAYMENT_WEBHOOK_SECRET_SEPAY`；SePay 只显示一次完整密钥。
4. 可选：把 `PAYMENT_WEBHOOK_CIDRS` 设为 SePay 公布的 IP 段。签名仍是主要校验。

### 校验签名

SePay 发送 `X-SePay-Timestamp`（Unix 秒）和 `X-SePay-Signature: sha256=<hex>`。签名是用密钥对 `<timestamp>.<原始请求体>` 计算的 HMAC-SHA256。手动验证一个请求：

```bash
printf '%s' "$TIMESTAMP.$BODY" | openssl dgst -sha256 -hmac "$SECRET" -hex
```

监听端口的响应：

| 情况 | 响应 |
|---|---|
| 签名有效 | `200`，正文 `{"success":true}`；已收到过的事件重发时同样如此 |
| 签名缺失或错误 | `401` `payment_signature_invalid` |
| 其他路径、方法，或未配置的渠道 | `404` |

找不到待支付订单、或金额不符的转账会进入员工的付款通知队列，不会改动任何订单。未设置 `PLATFORM_WEBHOOK_PORT` 时不运行监听端口。

## 接入第二个支付渠道

支付渠道位于 `platform-management/internal/billing/provider.go` 中的 `billing.PaymentProvider` 接口之后：

| 方法 | 职责 |
|---|---|
| `CreatePaymentRequest(o Order) (Instructions, error)` | 返回客户支付订单所需的付款指引 |
| `ParseNotification(body []byte, headers http.Header) (Notification, error)` | 校验并解析支付渠道发来的付款通知 |
| `QueryStatus(o Order) (Status, error)` | 向支付渠道查询订单的支付状态 |

接入第二个支付渠道的步骤如下：

1. 实现 `billing.PaymentProvider` 的三个方法。
2. 在 `billing.NewRegistry`（`platform-management/internal/billing/registry.go`）中注册该渠道，并在 `PAYMENT_PROVIDERS` 中绑定对应货币（例如 `vnd=manual,<currency>=<provider>`）。
3. 如果该渠道使用 webhook，设置 `PAYMENT_WEBHOOK_SECRET_<PROVIDER>` 并配置 `PLATFORM_WEBHOOK_PORT`。

当前版本未内置第二个真实支付渠道。
